# 代码导览

## 入口与数据路径

1. [`app/domain/models.py`](../app/domain/models.py) 定义六类提取结果、证据、冲突和用量契约。
2. [`app/adapters/parser.py`](../app/adapters/parser.py) 解析文本与 PDF，保留全局 Unicode 偏移，限制字节、字符和页数。
3. [`app/services/model_service.py`](../app/services/model_service.py) 依次处理缓存、模型调用、严格 JSON、Pydantic、原文支持和有限修复。
4. [`app/services/pipeline.py`](../app/services/pipeline.py) 编排固定步骤，合并分块结果，保留部分失败信息。
5. [`app/services/campus_review.py`](../app/services/campus_review.py) 在结构校验后检查招生材料的缺项、歧义、名额冲突与年份。
6. [`eval/run_eval.py`](../eval/run_eval.py) 将输出与独立编写的参考字段对照，记录失败分母。

## 固定流程与输入边界

模型只能返回数据，不能改变执行顺序或调用新工具。Parser、分类、提取、分析、摘要、校验和导出均由程序控制。
文档以 JSON 编码的数据传入提示词，没有 shell、浏览器或文档指令执行接口。
这种边界限制操作权限；它不能证明外部模型的判断不受恶意语义干扰。

JSON Schema 模式约束服务端输出，本地 Pydantic 继续检查枚举、字段类型和额外字段。
解析器还拒绝重复 JSON key，避免前值被静默覆盖。缺失事实用 `null` 或 `[]` 表示。

## 证据与冲突

每个非空事实必须对应连续原文片段；最终证据包含段落、页码和 `start:end` 偏移。
标量存在多个候选时置空并保留冲突值。列表合并去重，不使用摘要模型裁决冲突。
原文支持只证明内容能定位，不能证明字段归属或原文本身正确，因此评测另行比较参考字段。

校园审阅进一步把摘录证据关联到原 DOCX 的段落。招生人数与面试入围比例分别保留，
时间表述不自动规范化。来源不匹配时拒绝生成审阅包；未命中规则时仍保留待人工核对状态。
完整范围见[校园资料说明](CAMPUS_DATA.md)。

## 长文、调用与缓存

所有字符都进入分块，提取和分析覆盖每块，摘要再分层 Reduce。
长距离关系、切开的字段和语义冲突仍可能丢失，程序保留相应告警。
源文本、提示词、Schema 和输出预留共同进入上下文预算。

UTF-8 字节数是保守估算，不当作 provider usage。价格表缺少带日期、来源的条目时费用为 `null`。
坏 JSON、结构错误和无来源内容允许有限修复；超时、认证错误、拒绝和输出截断直接返回对应错误。
失败尝试也计入调用、耗时和用量。

缓存默认关闭。缓存键包含文档与分块哈希、模型、endpoint、完整提示词、Schema 和输出预算。
提示词摘要覆盖全部模板，任何模板变化都会让旧缓存失效。缓存只接收已校验结果。

## 验证范围

原有 40 条固定样例同时检查文档类型、字段、冲突和原文支持；故意错分类的案例可以通过 Schema，仍会被参考字段检出。
校园测试另行检查来源哈希、原 DOCX 段落、歧义时间、不补全年份和名额冲突。
测试与 Mock 时延不代表真实模型效果或线上性能，执行记录见[验证记录](VERIFICATION.md)。
